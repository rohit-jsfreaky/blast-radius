# Decisions

Any seat. One row per choice the requirements leave open. Decide; never wait.

| id | seat | choice | requirement it interprets (verbatim quote) | depends on it |
|---|---|---|---|---|
| D1 | coordinator | Language: TypeScript compiled at docker build to JavaScript, run on Node 22 (slim image, tsc/esbuild at build only). Alternative: plain JavaScript if simpler. No network at run time. | "Language, framework and storage are unrestricted." | all code |
| D2 | coordinator | Storage: in-memory state in ONE Node process; every write handler is synchronous (no await between read and commit) so concurrent requests are serialised and every write is atomic. No database. | "State need not survive a container restart" / "Concurrent requests must produce the same results as executing them one at a time in some order" | S-store, all write paths |
| D3 | coordinator | Passwords: Node built-in crypto scrypt with a per-user salt; tokens: 32 random bytes hex. No third-party hashing dependency. | "Passwords must be stored using a password-hashing function such as bcrypt, scrypt or Argon2" | auth, export/import |
| D4 | coordinator | Time zones: Node's built-in Intl (full ICU in the official image) only; one shared time module resolves local to instant with the first-occurrence rule and rejects nonexistent local times. No tz library downloaded. | "Offsets must follow the IANA rules for the specified zone and date." | availability, create, patch, moves, series |
| D5 | coordinator | Browser screens (stage 2 on): static HTML, CSS and vanilla JS served by the same Node process; client-side rendering; every route in the screen table returns the same HTML shell (history fallback). Fonts and icons come from npm packages copied into the image at build time, no CDN. | "Server-side and client-side rendering are both permitted." / "Runtime assets and dependencies must be included in the image." | UI |
| D6 | coordinator | Every write operation is a pure function `state -> (newState | error)` built on a copy-then-commit transaction helper, so a failed request never leaves partial state (atomic moves, series, replans reuse it). | "Retries and rejected requests must not create duplicate or partial bookings." | S-store |
| D7 | coordinator | Export `state` is the whole in-memory store as plain JSON including password hashes, tokens, idempotency receipts and a `version` field; import validates then swaps atomically; later stages must read older versions (missing fields default). | "It must accept an unchanged export produced by this service." | export/import, every later stage |
| D8 | coordinator | Shared code is declared in factory/shared.md as S<n> by the builder who writes it BEFORE others depend on it; builders agree file ownership in the room before starting. | mandate | all |
