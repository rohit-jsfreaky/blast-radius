# Decisions

Any seat. One row per choice the requirements leave open. Decide; never wait.

| id | seat | choice | requirement it interprets (verbatim quote) | depends on it |
|---|---|---|---|---|
| D1 | coordinator | Language: TypeScript compiled at docker build to JavaScript, run on Node 22 (slim image, tsc/esbuild at build only). Alternative: plain JavaScript if simpler. No network at run time. | "Language, framework and storage are unrestricted." | all code |
| D2 | coordinator | Storage: in-memory state in ONE Node process; every write handler is synchronous (no await between read and commit) so concurrent requests are serialised and every write is atomic. No database. | "State need not survive a container restart" / "Concurrent requests must produce the same results as executing them one at a time in some order" | S-store, all write paths |
| D3 | coordinator | Passwords: Node built-in crypto scrypt with a per-user salt; tokens: 32 random bytes hex. No third-party hashing dependency. | "Passwords must be stored using a password-hashing function such as bcrypt, scrypt or Argon2" | auth, export/import |
| D4 | coordinator | Time zones: Node's built-in Intl (full ICU in the official image) only; one shared time module resolves local to instant with the first-occurrence rule and rejects nonexistent local times. No tz library downloaded. | "Offsets must follow the IANA rules for the specified zone and date." | availability, create, patch, moves, series |
| D5 | coordinator | Browser screens (stage 2 on): static HTML, CSS and vanilla JS served by the same Node process; client-side rendering; every route in the screen table returns the same HTML shell (history fallback). | D6 | coordinator | Every write operation is a pure function `state -> (newState | error)` built on a copy-then-commit transaction helper, so a failed request never leaves partial state (atomic moves, series, replans reuse it). | "Retries and rejected requests must not create duplicate or partial bookings." | S-store |
| D7 | coordinator | Export `state` is the whole in-memory store as plain JSON including password hashes, tokens, idempotency receipts and a `version` field; import validates then swaps atomically; later stages must read older versions (missing fields default). | "It must accept an unchanged export produced by this service." | export/import, every later stage |
| D8 | coordinator | Shared code is declared in factory/shared.md as S<n> by the builder who writes it BEFORE others depend on it; builders agree file ownership in the room before starting. | mandate | all |
| D9 | builder-a | Plain Node 22.20 type stripping: `.ts` sources run directly with `node --disable-warning=ExperimentalWarning src/server.ts`, no compile step, no npm dependencies (erasable TS only, imports end in `.ts`). | D1 "TypeScript compiled at docker build ... | D10 | builder-a | Signup `display_name` is optional (defaults to the part of the email before `@`); wrong JSON type -> 400, `email`/`password` missing -> 422. Emails compare case-insensitively. | "`email` not of the form `local@domain`" / "A required field or query parameter is missing" | auth |
| D11 | builder-a | Idempotency receipt identity is user + method + path + key; a stored receipt is replayed only when the canonical JSON body matches, else 409 (same path) - a key on another path is independent. | D12 | builder-a | A local start is checked in the order: format, nonexistent DST time, opening hours/closing, slot grid. Opening-hours test is wall-clock: `start + duration <= closes`. | D13 | builder-a | Availability: validation (missing/format -> 422) runs before the restaurant lookup (404). Reservation `created_at` in seeded fixtures defaults to the reset time. | "All three parameters are required; a missing one is 422" | availability |
| D14 | builder-b | Create/patch/moves validate in order: key, body object (400), replay lookup, shape (missing or bad party_size/format 422; non-string restaurant_id/table_id/starts_at_local 400), restaurant 404, table 404, start (invalid_local_time, outside_opening_hours, not_on_slot_grid), party_exceeds_capacity, then overlap 409. Amend/moves check owner 404, cancelled 409, cutoff 409 BEFORE field validation. Omitted amend fields keep current values and are not re-validated. Receipts imported from stage 1 keep their original body unchanged (no table_ids added). Check order: both table_id+table_ids/duplicates 422 -> restaurant 404 -> unknown table 404 -> not a declared pair or >2 combination_not_allowed -> start rules -> capacity (summed) -> overlap 409. | "`table_id` is still accepted and means a set of one.
